# Fledgling

> A 5–10 minute browser game where every playthrough invents a new language and asks you to decipher it. Built for the [AI Engineer Hackathon Singapore](https://luma.com/aie-hack), 2026-05-09.

You crash on an island. Six villagers speak a language no human has ever spoken before. The phonology, the lexicon, and the grammar are all generated the moment you load the page. They want wood, oil, and flint to light the lighthouse beacon. Nobody will translate for you. Your only tool is a diary you fill in yourself by hovering over words and writing what you think they mean.

If your guess is right, the world responds. The baker hands you a bundle of logs. If it's wrong, she tilts her head and waits. The game never tells you which.

When the beacon lights and you climb to the lighthouse, the chief speaks to you over a live voice channel in that same generated tongue, and you answer her with your own voice. She was the closest friend of the field linguist who came before you. Then you choose: leave on the boat at first light, or stay.

---

## Why this isn't Duolingo

Duolingo teaches you a specific language by drilling. Fledgling teaches you how to learn any language at all. It drops you into one and gives you no choice but to do what real field linguists do: listen, guess, write it down, see if the world agrees.

The trick is that the language is invented per run. You can't have studied it before. You can't look it up. The 50-word lexicon, the suffix rules, the SOV word order, the phonotactics are all generated by GPT-5.5 from a seed when the page loads, then voiced by ElevenLabs in voices we picked for each villager. The game is the same; the language is never the same twice.

Anyone can do it. There's no prerequisite linguistics background, no instruction manual, no tutorial that drills vocabulary. A 17-second prologue tells you four things — you crashed, they don't speak your language, hover any word to write what you think it means, your guesses are the only translation you'll have — and then a child runs across the sand to greet you. From there, the village teaches you itself.

It's a cosy game. No fail states, no timers, no penalties. A wrong guess loops back. The methodology you use is the same one that's been used to document every endangered language on earth. Fledgling is a small, playable taste of that craft.

## The AI stack

Fledgling uses six AI services. Each one is doing something the others can't.

| Service | Role | Why this one |
|---|---|---|
| GPT-5.5 | Procedural language generator | Generates a full `LanguageSpec` per seed: phonology, 50-word lexicon, morphology rules, syntax. Same seed always produces the same language, so you can share a tongue by sharing a seed. |
| Groq (Gemma 4 70B) | NPC frame-to-frame responder | When an NPC "hears" the player's frame, Groq emits a response frame in JSON-object mode, validated against our `validateFilledFrame` schema with a retry-on-error loop. Gemma 4 70B on Groq's inference stack gives us sub-second turnaround, which is what makes village conversations feel like conversations. |
| ElevenLabs Turbo v2.5 | Real-time streaming TTS for every village line | Each NPC has a hand-tuned voice profile (stability, similarity, style). Lines stream over a `stream-input` websocket so audio starts within 300 ms. The village sounds spoken instead of read. Lipsync timings come back in the same stream. |
| Gemini 3.1 Flash Live | Bidirectional voice for the climax | At the lighthouse, you stop picking from menus and talk. Your microphone streams Int16 PCM up; Hala's voice streams down. She knows what items you brought, whether you read the predecessor's journal, and the predecessor's generated name, all stitched into the system prompt from live world state. |
| Convex | Real-time NPC state and dialogue event log | Every NPC's position, action, inventory, and the world clock live in Convex. The Phaser engine subscribes; tick updates land in the scene graph at 30 in-game minutes per 2 seconds wall-clock. The dialogue event log doubles as the source for ambient overhearing. |
| Anthropic Claude | Design-time co-author | Six sibling Claude Code sessions ran in parallel during the hackathon (engine, language, voice, story, sim, orchestrator), coordinating through a shared `agents/` scratch space and an Obsidian Kanban. The repo is the artefact of that collaboration. |

The split between ElevenLabs for villagers and Gemini Live for the climax is deliberate. Most village lines are short, written, and deterministic. ElevenLabs handles them with sub-300 ms first-byte latency and a per-NPC voice. The climax is the one beat where the player should speak freely, and Gemini Live makes that feel like a real conversation in a language they've spent the last ten minutes learning.

## The frame system

The thing that makes the whole stack work is a small typed semantic layer. Every utterance, NPC line or player choice, is authored as an English string and a *frame*: a typed predicate-and-roles object that the language module can encode into any generated language and decode back.

```
GIVE(agent: self, recipient: listener, theme: WOOD)  [imperative]
   ↓ encodeFrame(spec)
"tova-n ki-ra ne-ko sov"     ← in this run's language
   ↑ decodeFrame(spec)
GIVE(agent: self, recipient: listener, theme: WOOD)  [imperative]
```

Sixteen frames cover the village's speech acts: `GIVE`, `TAKE`, `MOVE`, `WANT`, `BE_AT`, `HAVE`, `SEE`, `SAY`, `MAKE`, `EAT`, plus the social spine `GREET`, `AFFIRM`, `DENY`, `DECIDE`, `KNOW`, and `THANK`. Five entity types (`ANIMATE`, `ITEM`, `LOCATION`, `ABSTRACT`, `EVENT`), three moods, three tenses, plus negation and nesting.

That single contract is what lets a procedurally-generated language be playable. The dialogue is authored once; the language module realises it in every tongue the generator can produce.

## Architecture at a glance

```
┌─ Phaser 4 + TypeScript (browser) ─────────────────────────────────┐
│                                                                    │
│  scenes/  ─→ NPCInteraction ─→ DialogueOverlay ──┐                 │
│                                                  ▼                 │
│  src/lang/  frames.ts • encoder • decoder • diary • respond        │
│       │                                                            │
│       ├─→ ElevenLabs streaming TTS  (src/voice/elevenlabs-client)  │
│       └─→ Gemini Live bidirectional  (src/voice/gemini-live)       │
│                                                                    │
│  src/integration/  ConvexClient subscriptions + mutations          │
└────────┬───────────────────────────────────────────────────────────┘
         │
         ▼
┌─ Vercel ─────────────┐   ┌─ Convex ─────────────────────────────┐
│  /api/gemini-token   │   │  npcs • dialogueEvents • worldState  │
│  /api/elevenlabs-token │ │  tick loop, real-time subscriptions  │
└──────────────────────┘   └──────────────────────────────────────┘
```

Two thin Vercel functions mint short-lived tokens so the long-lived API keys never touch the browser. The Phaser engine subscribes to Convex over websockets and renders deltas through `requestAnimationFrame`-coalesced handlers, which keeps the scene graph from thrashing on tick events. Voice is shared across providers through one `StreamingAudioPlayer` that gaplessly concatenates PCM chunks from either source.

- Phaser 4, TypeScript, Vite
- Convex for real-time NPC state, dialogue events, world clock (`src/integration/`)

- Groq Gemma 4 70B for NPC response frames
- ElevenLabs Turbo v2.5 for streaming village TTS (`src/voice/elevenlabs-client.ts`)

- Fal for pixel-art sprites (build-time)
- Lyria for ambient music
- Hosted on Vercel

## Develop

```bash
npm install
cp .env.example .env.local   # fill in keys (see below)
npx convex dev               # first-run browser auth, then keep running
npm run dev                  # Vite on http://localhost:5173
```

Required env:

| Variable | Purpose |
|---|---|
| `VITE_CONVEX_URL` | Auto-populated by `npx convex dev` |
| `GEMINI_API_KEY` | Server-side; minted into ephemeral tokens by `/api/gemini-token` |
| `ELEVENLABS_API_KEY` | Server-side; minted into signed websocket URLs by `/api/elevenlabs-token` |
| `GROQ_API_KEY` | Server-side; used by the NPC response pipeline |
| `OPENAI_API_KEY` | Build-time; used to generate `LanguageSpec`s offline |

| Script | Purpose |
|---|---|
| `npm run dev` | Vite dev server with `/api/*` middleware |
| `npm run build` | Type-check, then production build |
| `npm run typecheck` | Type-check only |
| `npm run test` | Vitest |
| `npm run demo` | CLI demo of the language pipeline |

## Layout

- `src/scenes/` — Phaser scenes (Crash → Village → Hut → Lighthouse)
- `src/sim/` — dialogue trees, frame attachments, NPC roster, pickup tiles
- `src/lang/` — frame system, encoder/decoder, gloss, parse, respond, generator
- `src/state/` — game-side flags, inventory, handover bridge
- `src/integration/` — Convex client, typed subscriptions, mutation wrappers
- `src/voice/` — ElevenLabs streaming TTS, Gemini Live, shared audio pipeline
- `src/ui/` — DialogueOverlay, DiaryOverlay, JournalOverlay, EndScreen, HUDs
- `convex/` — schema, queries, mutations, tick loop, seed
- `api/` — Vercel serverless routes (`gemini-token`, `elevenlabs-token`)
- `agents/` — operational notes shared between the six parallel Claude Code sessions that built this

Planning, research notes, and decision logs live one level up alongside this directory.

## A note on the people who built this

Six Claude Code sessions ran in parallel. Each one owned a lane (engine, language, voice, story, sim, orchestrator) and coordinated through `agents/` and an Obsidian Kanban. That working method is itself part of the submission: a small experiment in what coherent multi-agent product work looks like when the agents have roles, file ownership, and a shared scratch space, instead of a single firehose prompt.

The result is a game you can finish in ten minutes, whether you've ever thought about linguistics or not. That's the point.
